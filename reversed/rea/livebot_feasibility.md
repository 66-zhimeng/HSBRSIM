# 实时对局自动化（Live Bot）可行性记录（2026-10-18）

> 用户授权：**忽略 botting/ToS 顾虑**，目标是自动对局、持续采集真实 Power.log/HDT 数据。
> 本文记录已实测的输入/窗口/导航结论，供 `hsbg/live/` 实现使用。

## 1. 结论：可行（已实测）

- 目标进程：`Hearthstone.exe` PID 33768，窗口标题 `炉石传说`（PowerShell 显示乱码，Unicode 正常）。
- 窗口 rect：`(-7, 0, 1929, 1048)`（1936×1048，窗口化；DPI 100%，屏幕 1920×1080）。
- **鼠标/键盘注入均有效**（pyautogui / SendInput）——之前“点击无效”是**坐标换算错误**
  （把 1708×961 的预览图坐标当成了 1920×1080 实际坐标，偏小约 12%）。
- 已实测导航路径：
  1. 主菜单（`酒馆战棋` 按钮实际屏幕坐标约 **(960, 411)**）
  2. 酒馆战棋大厅（页面含 `开始` 圆形按钮约 **(1370, 795)**、`返回` 约 (1537, 966)）
  3. 传统对战模式误入后 `返回` 可回到主菜单。
- 关键：**所有坐标必须基于 1920×1080 全屏截图**（不要用 read_image 的预览缩放坐标）。

## 2. AgenticAssistant 结论（已核查）

- 0.5.3/0.6.1 PyInstaller 包内含 `bgassistant`（catalog）与 `bgcontroller`（
  `client.memory`/`client.mono`/`state`/`tags` 等），**只读**游戏状态；
  使用说明明确“客户端不自动点击游戏”；无自动操作接口；本地队列 DPAPI 加密。
- 因此自动化必须由我们实现输入层（已完成可行性验证）；AgenticAssistant 仅可作为
  状态读取/提示的参考实现（可选复用其内存读取，见 rea-operator 任务）。

## 3. 下一步实现（已在推进）

1. `hsbg/live/wininput.py`：窗口发现、DPI、焦点、相对坐标点击/拖拽/按键、F12 暂停。
2. `hsbg/bridge/live_log.py`：最新 Power.log 增量监听 → session/game/turn/phase/choice 事件。
3. `hsbg/live/runner.py`：英雄选择 → 招募（买/打/卖/技能）→ 战斗等待 → 结算 → 下一局。
   - 第一阶段可**盲操作**（固定坐标），仅用 Power.log 判断阶段/回合；
   - 第二阶段接 `tools/live_state_mem.read_live_state()`（rea-operator）读取 shop/hand/board 再决策。
4. 数据落盘：每局记录 Power.log 路径/起止时间/名次；与 HDT 日志对齐；异常截图。

## 4. 风险与注意（用户已知悉）

- 自动化对局会影响账号战绩/评级，且存在封号风险（用户已指示忽略该顾虑）。
- 游戏/窗口分辨率变化会使坐标失效 → 配置文件化 + 校准脚本。
- 战斗阶段不操作；若状态识别失败则暂停（F12）并截图，避免误操作。
